# Наборы и запланированные покупки

В турнирном списке персонажей рядом с каждой строкой и внутри раскрытых турнирных ростеров рядом с именем персонажа есть стрелка ↗. Она есть и у распознанных персонажей текстовых листов. Она переводит в раздел «Персонажи» и открывает соответствующую карточку; кнопка «В „Персонажи“» в турнирной деталке делает то же. Используются прежние inventoryIds для сопоставления версий, а не поиск по похожему имени.

В карточке персонажа — блок «В каких наборах». Нажатие на набор открывает его фотографию, точный состав миниатюр и отметки имеющихся персонажей. Из состава можно перейти к карточке знакомой версии. Персонажи ещё не добавленных в каталог версий показываются по имени. Состав учитывает только `Character`, не выдаёт дополнительные StatCard за отдельные миниатюры. Количество учитывается по `amount`.

По уточнению пользователя **магазины, цены, наличие и ссылки на покупку исключены**. Ни интерфейс, ни публичный снимок не используют поле shop.

«☆ Запланировать» / «★ В планах» добавляет и удаляет набор из вишлиста. Раздел меню **09 Запланированные покупки** содержит «Мой вишлист», «Все наборы» и поиск по названию, коду, персонажу. Планирование не меняет коллекцию моделей или ростеры. Навигация учитывает несохранённые правки ростера.

## Данные и хранение

Снимок `data/box-sets.json` загружен 21 октября 2026 из публичных Jarvis `/api/box_sets` и `/api/box_sets/<CODE>`. 198 наборов, 198 локальных изображений, 155 наборов с миниатюрами. Для всех связей boxSets из текущего каталога подтверждено наличие персонажа в detailed content набора. Фото: `assets/box-sets/`; CP03 отдаёт JPEG под URL .png — сохранён с расширением jpg без обработки. Скрипт `scripts/prepare_box_sets.py` кеширует detailed responses в QA и скачивает максимум 4 запроса одновременно. Runtime-обращений к Jarvis для наборов нет.

В state, localStorage и экспорте JSON появился необязательный массив `wishlist` с кодами наборов. Старое сохранение без поля читается как пустой вишлист, дубли убираются. При импорте старого файла список покупок очищается; это явно указано в подтверждении импорта. Неизвестные корректные коды из будущих снимков сохраняются и показываются как «Набор CODE», с честным отсутствием данных; можно удалить их из планов. Синхронизация между вкладками использует прежний storage event. Личная коллекция/ростеры/партии не попадают в опубликованную сборку.

Основной код: `frontend/src/stores/library.js` и `frontend/src/purchases.jsx`, `purchases.css`; инициализация в frontend/src/bootstrap.js; интерфейс полностью React, состояние MobX. `tests/stores.test.cjs` проверяет снимок/все связи и совместимость сериализации. `tests/e2e/purchases.spec.cjs` проверяет маршрут из турниров, картинку/состав, независимость от коллекции, вишлист, поиск, reload, вторую вкладку, экспорт, импорт legacy, мобильную ширину и guard несохранённого ростера.

## Запланированные персонажи и купленные коробки

Персонаж из набора в вишлисте получает жёлтую отметку **«Запланирован»** вместо «Нет в коллекции»: в турнирной деталке, внутри турнирного ростера, в редакторе/выборе состава и в деталке коробки. Наличие имеет приоритет: уже имеющиеся персонажи остаются зелёными. План не считается наличием и не делает ростер доступным из коллекции.

У каждой коробки есть кнопка **«Отметить купленным» / «✓ Куплен»**. Она добавляет всех её персонажей в коллекцию, убирает набор из вишлиста. В разделе09 появилась вкладка «Купленные». Можно отменить покупку: сохраняются ручные отметки и персонажи других купленных коробок. Отдельный checkbox персонажа из купленного набора остаётся включённым и управляется отметкой самой коробки; это объяснено tooltip. Можно вернуть коробку в планы после снятия покупки.

Совместимое сохранение version1 расширено `purchasedSets` (коды коробок) и `manuallyOwned` (ручные отметки). `owned` по-прежнему содержит полную эффективную коллекцию для прежних читателей/AtlasBridge. Для старых файлов `manuallyOwned` берётся из `owned`, список купленных коробок пуст. Данные нормализуются при boot/import/storage и действии покупки; теги и фильтры коллекции видят объединение ручных моделей и известного каталогу содержимого купленных наборов. Неизвестные персонажи внутри купленной коробки отмечаются как имеющиеся в её деталке, а после появления в каталоге автоматически попадут в коллекцию. Все поля входят в экспорт. При неудачном сохранении покупка откатывается.

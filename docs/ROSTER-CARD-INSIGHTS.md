# Карты персонажа и турнирная статистика карт

В редакторе ростера рядом с «Убрать» у каждого персонажа есть «Добавить карты». Открываются связанные Team Tactics из снимка Jarvis; персонаж автоматически выбран в статистическом контексте. Чекбокс «Только связанные карты» позволяет показать все тактики, оставив контекст персонажа.

В фильтрах тактик есть «Персонаж карты»: можно выбрать любого персонажа и оставить только связанные с ним карты. При открытии через «Добавить карты» персонаж уже выбран. «Персонаж карты: любой» снимает ограничение. Этот фильтр независим от поля «Персонаж в ростере», которое задаёт только контекст популярности и баллов.

Связь повторяет логику Jarvis: `requirementsItems.mandatory_character`, `optional_character`, `mandatory_alter_ego`, `optional_alter_ego`, `mandatory_character_with_alter_ego`. Используется `actAs`; Hulkbuster дополнительно считается Iron Man. Для комбинированного требования одновременно совпадают имя персонажа и alter ego. Само совпадение аффилиации не делает карту персональной. Это фильтр связанных карт, а не полная проверка возможности разыграть карту при текущем составе.

В каждой строке тактики дополнительно показано «Персонаж: Angel» или список связанных персонажей. Подпись вычисляется по требованиям самой карты и не меняется при выборе другого статистического контекста. У общих карт без персональных требований подписи нет.

## Контекст и показатели

В окнах тактик и кризисов есть отдельные фильтры «Аффилиация ростеров» и «Персонаж в ростере». Они применяются пересечением. Обычный фильтр аффилиации самой карты остаётся отдельным и не меняет статистический контекст.

- Популярность: `100 × Σ(1/M для списков с картой) / Σ(1/M для всех пригодных списков в контексте)`, где M — число вариантов списка у одного выступления. Число ростеров рядом — обычный целый счётчик вариантов списков с картой.
- Сумма: сумма прежних `pointsShare = performancePoints/M` по выступлениям с картой, включая отрицательные значения.
- Сглаженное среднее: прежний `AtlasCore.scoreSummary`; нулевое условное выступление в знаменателе, до 4 разных оценённых выступлений — 0.
- Для популярности результат выступления не требуется; provisional-списки могут участвовать. Для суммы/среднего нужны завершённые оценённые выступления, как и в остальном архиве.
- Сортировки: популярность (по умолчанию), сумма баллов, средний балл, алфавит. Сортируются исходные числа, отображаемое округление на порядок не влияет.

Данные берутся из уже встроенного турнирного архива; новые runtime-запросы к Jarvis/Longshanks не нужны. Персонажи сопоставляются с архивом через inventoryIds, чтобы объединять переиздания одной игровой версии, не смешивая произвольно разные версии одного героя.

## Разбор и покрытие

Печатные версии карт объединены выбранной канонической записью cardFamily. Существующие алиасы Longshanks/Jarvis вынесены в `TournamentImport.resolveCard`, который используется и импортом ростера, и статистикой. Повтор карты внутри списка считается один раз.

Сначала используются структурированные tactics/crises. Если их нет — разбираются секции rawText, включая заголовки TTC / Secure / Extract, маркеры Restricted и обозначения карты/Threat. Нет нечёткого угадывания похожих названий. Если хотя бы одно название типа карт не распознано или объявленное число TTC не сходится, весь этот список для соответствующего типа исключается из числителя и знаменателя. Отсутствующий перечень не считается перечнем без карты. Явный «Team Tactics 0» может быть распознанным пустым перечнем.

На текущем снимке 2520 ростеров полностью разобраны тактики в 2464, кризисы в 2453. Остались, среди прочего, французские названия, сокращения, опечатки и листы-ссылки. Покрытие каждого выбранного контекста показано в окне; это показатели распознанной выборки, не утверждение о всех неразобранных листах.

## Реализация и проверка

- `roster-card-insights.js` — чистый индекс/когорты/отношения; результаты контекста кешируются.
- `frontend/src/stores/rosters.js` — действия персонажа, фильтры и сортировка, выбор без изменения схемы сохранений. Контекст — временный UI, не записывается в ростер.
- `tournament-import.js` — общий resolver прежних алиасов.
- `tests/roster-card-insights.test.cjs` — пять проверок отношений Jarvis, пересечения когорт, весов вариантов, исключения пропусков, отрицательных баллов и порога среднего.
- `tests/e2e/roster-card-insights.spec.cjs` — реальный редактор, автоконтекст Hulk, пересчёт по аффилиации/персонажу, все сортировки, выбор/сохранение тактики, статистика кризисов и телефонная ширина.
- Визуальные артефакты: `previews/roster-card-popularity-tablet.png` и `previews/roster-card-popularity-phone.png`.

Личные сохранения и партии остаются прежними. Текстовые листы не изменяются в исходном архиве; статистический индекс строится отдельно.

## Кризисы и Challenger

В выборе кризисов доступны те же популярность, сумма и сглаженное среднее баллов, контексты аффилиации/персонажа в ростере и четыре сортировки. Персональных владельцев у кризисов нет: персонаж здесь задаёт статистический контекст.

«Только Challenger» включён при каждом открытии выбора кризисов. Фильтр берёт `challengerStatus === "legal"` из публичного API Jarvis; Standard фильтруется независимо. Снятие Challenger показывает остальные кризисы, не удаляя уже выбранные из ростера. В строках показан статус Challenger. Фильтр ограничивает список предлагаемых карт; турнирная когорта и знаменатель популярности остаются прежними.

Статусы Challenger обновлены 20 октября 2026 из [Jarvis API](https://www.jarvis-protocol.com/api/crisis_cards), сохранены отдельно от замороженного текста правил (`challengerSource` в снимке). Дополнительно проверено назначение Challenger по [документу AMG](https://www.atomicmassgames.com/mcp-op/): это отдельное ограничение кризисов, его нельзя заменять статусом Standard. Скрипт `scripts/prepare_roster_cards.py` сохраняет статус и даты ротации при будущих обновлениях.

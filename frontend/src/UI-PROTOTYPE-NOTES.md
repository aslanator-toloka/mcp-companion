# Прототип упрощения интерфейса

Вопрос: какая иерархия уменьшает перегруз и сохраняет быстрый доступ к игровым действиям?

Запуск из `pages`: `npm run prototype`.
URL: http://127.0.0.1:4186/mcp-companion/?prototype=ui&variant=A

Один существующий маршрут приложения, два варианта через `variant=A|B`:

- A: три главных раздела в боковой панели, каталог списком, отдельная страница персонажа.
- B: старт с незавершённой партии и следующего ростера, горизонтальная навигация.

Оба используют настоящий каталог и существующие компоненты `StatSurface` / `StatControls` из `cards.jsx`, исходную `card-viewer.css`, данные иллюстраций и раскладки. Для этих компонентов сервер подставляет отдельные stores с хранением в памяти. Production-компоненты и их поведение не изменяются. Коллекция, ростер, счёт, HP, энергия и активации — общие демонстрационные данные в React state, без localStorage и реальных изменений. Перезагрузка сбрасывает демо. Ссылки «Ещё» открывают существующее приложение в новой вкладке. Текущая production-сборка и её entry point не меняются. Сервер прототипа собирает отдельный development-бандл в памяти; переключатель исключается при production-сборке.

Проверить: найти персонажа → открыть карту → добавить в состав → перейти к демо-бою → изменить HP/энергию → активировать → отменить → следующий раунд. Персонаж открывается отдельной страницей `screen=character&card=<slug>&from=<screen>`. Кнопка возврата и Back браузера сохраняют поиск, фильтры и прокрутку списка.

Решение после просмотра: **ожидается выбор пользователя**. Победившую структуру реализовать в основном UI; временные компоненты, CSS и сервер затем удалить.

Обратная связь пользователя: повторяющиеся названия разделов, пояснения и рекламные фразы сами создают перегруз. Во втором проходе удалены верхняя служебная полоса, breadcrumbs, заголовок каталога, слоганы и повторные объяснения. На телефоне навигация собрана в одну строку. Служебная отметка о демо вынесена в переключатель прототипа. Сохранять текст, если он называет действие, показывает состояние или помогает решить конкретную неоднозначность.

Уточнение пользователя: упрощение интерфейса не означает изменение игровой карты или объединение экранов. Вариант с двумя колонками и самодельный список характеристик/способностей удалены. Игровая карта сохраняет исходный вид, персонаж имеет собственную страницу. В дальнейших итерациях менять навигацию, повторы текста и вспомогательные действия; сохранять понятные существующие сценарии.
